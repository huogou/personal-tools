### 2.2 页签与两页

```
┌───────────────────────────────────────────────────────┐
│  备份   │  相册                                        │ ← 页签条 32px（tkinter 自绘）
├───────────────────────────────────────────────────────┤
│  「备份」页（tkinter，浅色）      「相册」页（WebView2，深色） │
│  S1 标题 / S2 路径 / S3 选项                          │
│  S4 建议 / S5 任务 / S6 日志                           │
└───────────────────────────────────────────────────────┘
```

- **页签条 32px**：选中页签顶部 2px 主色指示条（`#2F6FED`），tkinter 侧渲染。
- **「备份」页**：V1.2 六区结构，**浅色**，全部为 tkinter 原生控件；**日志区仅此页拥有**。
- **「相册」页**：**整个页面（分类栏 / 工具条 / 网格 / 状态条）都在 WebView2 内渲染**，tkinter 只承载一个空的 `Frame` 容器。首次切入才懒启动 WebView2。

> ⚠️ **关键事实**：当前两页是**两套视觉体系**——备份页浅色（`#F5F7FA` 底 + 白卡片），相册页**深色**（`#101418` 网格底 + `#1A2027` 条底）。两者靠同一品牌色 `#2F6FED` 勉强对齐，但**整体观感像两个软件**（06 号 §四「一致性要求」已承认此点）。

## 五、必须守住的红线（设计不得违反）【已验证（红线原文）】

沿用冻结包红线 + 任务书 §五、§八，本轮设计**全部继承**，其中与本设计强相关的：

1. **不得破坏已修复的 WebView2 播放链路**（`sync_controller_bounds` 可见性修复、起播超时、单实例占位、完整释放 `src`）。
2. **不得取消分页**（现 200/页 + 滚动加载）。
3. **纯离线**：不监听端口、不发起网络请求、不依赖在线字体/远程图片/CDN。
4. **零原始文件破坏**：对原片只读；写入只落输出目录。
5. **不得静默降级**：播放失败必须显式提示，不得无声换源。
6. **不得把未实现功能做成可点击入口**（任务书 §4.2）。
7. **不得宣称已实现/已测试**（任务书 §八）。
8. 窗口/DPI 兼容：Windows 11 常见尺寸与缩放。

## 七、结论

1. **可复用资产**：8 态状态机骨架、播放契约 P-1…P-10、桥接 API 22 个方法、分页与懒加载、三轨兜底——**这些是行为资产，全部保留**，本轮只重做**信息架构 + 视觉 + 交互呈现**。
2. **必须新增（后端）**：普通照片清单、异常项目清单、搜索/排序/筛选、设置、播放查看界面所需数据（进度/时长/信息）。这些在设计中**必须标注为「需后端支持」**，不得画成现有入口。
3. **核心设计任务**：把当前「深色、单层、工具式」的相册页，重构为**浅色、层次分明、Windows 11 现代相册观感**的客户端；并在**不超出已验证能力**的前提下，把任务书要求的导航/工具栏/播放/异常/空态/设置**画出目标形态并逐项标注「已实现 / 需后端 / 未来规划」**。
4. **主线风险**：任务书要求的导航分类（普通/异常/设置）与工具栏能力（搜索/排序/筛选）**超出当前后端**；若设计成可点入口即违反红线 6。本设计采用**「目标形态 + 状态标记」**策略（设计稿中未来项以禁用态/示例标注呈现，规格文档逐项标红）。
