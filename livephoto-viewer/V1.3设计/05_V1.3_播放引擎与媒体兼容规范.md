# 05 · V1.3 播放引擎与媒体兼容规范

> 起草：CodeBuddy（开发 AI）｜日期：2026-11-02｜状态：**V1.1 修订版**（落实评审 R-3/R-9 与 ChatGPT 复核裁定：D5 通过、build_html 丙案、build_preview_html 顺延 V1.4、GIF 点击状态管理）
> 本份定义「点开才播、播完回静止」的**可执行契约**，以及媒体三轨兜底与转码/缓存/导出规格。

---

## 一、播放契约（最高优先级，不得妥协）

> 用户原话：「只有用户点击图片才会播放，不点击就不播放的那种」

### 1.1 硬性规则

| # | 规则 | 违反示例 |
|---|---|---|
| P-1 | 卡片默认呈现**静止封面**（静态图像），**不得**默认动 | 默认加载 GIF 循环 |
| P-2 | **任何**播放必须由一次真实用户点击事件触发（`click` / `pointerup` / 键盘 `Enter`/`Space`） | `mouseenter` 自动播、`setTimeout` 自动播 |
| P-3 | 播放**结束**后自动恢复到静止封面（400ms 淡出） | 播完停在最后一帧算"完成" |
| P-4 | 再次点击 → **从头重播**（不是继续，也不是忽略） | `currentTime` 未归零 |
| P-5 | 同时**最多 1 个**卡片播放 | 多卡片并发解码 |
| P-6 | 播放中点击 → **停止并回到封面** | 无法停止 |
| P-7 | `Esc` → 停止播放并回封面 | — |
| P-8 | **悬停不得触发播放**（D5 裁定，同时废除现有网页查看器的 `mouseenter` 自播） | 悬停即动 |
| P-9 | 播放失败必须**显式提示**并给出可执行入口，禁止静默换源、禁止空白卡片（红线 L14） | 静默回退到别的源 |
| **P-10**（V1.1 新增，复核裁定） | **点击状态管理必须幂等**：连续快速点击、`loading` 态中重复点击、双击等情况下，状态机不得错乱——同一卡片在 `idle→loading` 转换期间忽略后续点击；`playing` 与 `idle` 的切换必须原子完成；任何点击只触发一次状态迁移 | 连点导致封面/GIF 显隐错乱、两张卡片同时处于播放态、`ended` 后残留 `playing` 类 |

### 1.2 单卡片状态流转

```
        idle(静止封面)
           │  用户点击
           ▼
        loading(封面 + 加载指示) ──失败──▶ failed(封面 + ⚠ + 提示 + 入口)
           │ 媒体就绪
           ▼
        playing(视频帧 + ▶) ──用户点击──▶ idle
           │  ended 事件
           ▼
      回到 idle（400ms 淡出）
```

**注**：`ended` 事件是唯一自动回到 `idle` 的路径（P-3），它由**播放结束**触发，不是由时间轴驱动。

## 二、媒体三轨判定

### 2.1 轨道定义

| 轨 | 来源 | 生成方式 | 何时使用 |
|---|---|---|---|
| **T1 原视频直解** | 源/备份中的 `.mov` / `.mp4` / `.m4v` | 无需生成 | 浏览器内核声明支持该编码时（`<video>` `canPlayType` 判定） |
| **T2 转码 MP4** | 原视频 → H.264 MP4 | ffmpeg `libx264`，缓存复用 | T1 不可用时 |
| **T3 GIF** | 原视频 → GIF | ffmpeg，**已有产物** | T1/T2 均失败时 |

### 2.2 判定流程

```
① <video>.canPlayType('video/mp4; codecs="avc1.42E01E"')  非空 → 走 T1
   <video>.canPlayType('video/mp4; codecs="hvc1.1.6.L93.B0"') 非空 → 走 T1
② T1 触发 error 事件 → 尝试 T2（检查播放缓存；无则现场转码）
③ T2 失败（ffmpeg 缺失 / 磁盘满 / 源文件损坏）→ 尝试 T3
④ T3 不可用 → failed 态：显示「这段实况暂时播不出来」+ 原因 + 入口「用系统播放器打开原文件」
```

### 2.3 兜底矩阵

| 场景 | T1 | T2 | T3 | 最终可见 |
|---|---|---|---|---|
| `.mp4` / H.264 | ✅ | 不触发 | 不触发 | 正常播放 |
| `.mov` / HEVC，Edge 可解 | ✅ | 不触发 | 不触发 | 正常播放 |
| `.mov` / HEVC，Edge 不可解 | ❌ | ✅ | 不触发 | 转码后播放（首次有等待，状态条提示「正在准备可播放版本…」） |
| T2 转码失败 | ❌ | ❌ | ✅ | GIF 播放（**循环**，UI 标注「动画版本」） |
| T3 也不可用 | ❌ | ❌ | ❌ | `failed` 态 + 可执行入口 |
| 源视频损坏 | ❌ | ❌ | ❌ | `failed` 态（**不得**说"照片损坏"，说"这段实况的视频读不出来"） |

> **UI 必须标注当前轨**：T3 情况下角标写「动画版本」并提示「GIF 会循环播放」，避免用户误以为这是完整实况（红线 L7：程序做不到的能力不得暗示）。

## 三、转码规格（T2）

```python
# ffmpeg 参数（imageio-ffmpeg 内置 7.1，已验证含 libx264 编码器）
-i <源视频>
-map 0:v:0  -map 0:a:0?          # 音轨可选（实况照片自带声音）
-vf scale=trunc(iw/2)*2:trunc(ih/2)*2   # 尺寸取偶，避免 yuv420p 编码失败
-c:v libx264 -preset medium -crf 22
-pix_fmt yuv420p -profile:v main -level 4.0
-movflags +faststart               # moov 前置 → 播放秒开
-c:a aac -b:a 128k -ac 2
<输出 mp4>
```

| 项 | 值 | 理由 |
|---|---|---|
| 容器/编码 | MP4 / H.264 (libx264) | 安卓、微信、QQ、Edge 全通吃 |
| 像素格式 | `yuv420p` | 兼容性必需 |
| Profile/Level | `main` / `4.0` | 比 `high` 覆盖更广的安卓设备 |
| CRF | 22 | 质量/体积平衡（实况片长 2–3 秒，体积通常 < 2 MB） |
| faststart | 开 | 网络/本地播放均秒开 |
| 音频 | AAC 128k 立体声，**无音轨则不生成** | 实况照片的"现场声"是体验的一部分 |
| 分辨率 | **不放大、不裁剪**，仅在超宽时限制到 1440（可选，默认不限制） | 保持画质 |

## 四、缓存策略

| 项 | 规定 |
|---|---|
| 缓存目录 | `输出目录/播放缓存/`（含 `video/` 与 `cover/`） |
| 缓存键 | `sha1(相对路径 + "|" + mtime_ns + "|" + size)` 前 16 位 |
| 文件名 | `video/<key>.mp4`、`cover/<key>.jpg` |
| 复用 | 命中键且文件存在 → 直接用，**不重复转码**（增量语义，与 `.processed.json` 无关） |
| 失效 | 源文件改动（mtime/size 变）→ 键变化 → 自动重新生成；旧文件按 LRU 清理 |
| 清理 | 「播放缓存」超过 **2 GB** 或 **30 天**未访问 → 清理（仅清理本工具创建的缓存目录，绝不触碰其他目录） |
| 写失败 | 磁盘满/权限 → **显式提示**并降级到 T3，不得静默（红线 L14） |
| 空间预检（**V1.1 新增，R-9/复核补充**） | **批量 T2 转码或批量导出 MP4 开始前**，对缓存/导出目录所在盘做一次**粗空间估算**（沿用 V1.2 L4 精神）：估算不足 → 显式提示「空间可能不够」并允许用户选择继续或取消；**预检超时/失败 → 明确标注「未完成空间检查」，不得静默放行**；**任何情形下不得自动删除文件**（含缓存清理仅在 §四规则内执行，绝不触碰用户文件） |
| 只读源 | 缓存只写输出目录，**源目录零写入** |

## 五、封面抽取规格

| 项 | 规定 |
|---|---|
| 来源 | **视频首帧**（沿用 `extract_cover`，HEIC 不需解码——绕开 HEIC 兼容问题） |
| 参数 | `ffmpeg -i <视频> -vframes 1 -q:v 3 <jpg>` |
| 缩略图尺寸 | 宽 **360px**（网格卡片实际显示宽度 ≤ 180px，360 足够 2× 高分屏） |
| 目录 | `播放缓存/cover/<key>.jpg`；无缓存时使用备份产物 `网页查看器/thumb/<name>.jpg`（若已存在，直接复用，零额外转码） |
| 兜底 | 抽帧失败 → 用 GIF 首帧；再失败 → 显示占位图标 + 文件名，**不显示空白** |

## 六、导出 MP4（安卓分享，R-11）

| 项 | 规定 |
|---|---|
| 入口 | 「相册」页工具条「导出 MP4」；或选中卡片右键「导出 MP4」 |
| 产物目录 | `输出目录/安卓分享/`，文件名 `<原基名>.mp4`（同基名冲突时追加 `-2`、`-3`） |
| 规格 | 同 §3 转码规格（**H.264 + AAC + faststart**） |
| 行为 | 已存在且规格一致 → 跳过并提示「已是最新」；**不重复转码** |
| 批量 | 支持多选批量导出；导出过程显示进度，可取消（取消 = 当前文件完成后停）；**批量开始前执行 §四空间预检（V1.1 新增）** |
| 文案 | 明确告知用途：「这是安卓手机可以直接播的 MP4，发到微信/QQ 后，对方点一下才播放」（红线 L7：不得宣称"安卓图库原生识别实况照片"——**它不会**，只能说"视频形式"） |
| 附带 | 导出完成后提供「打开所在文件夹」入口 |

> **价值说明**：该产物同时解决用户最初诉求（发给安卓朋友）。在安卓聊天软件中，MP4 显示为**一帧静止首帧 + 播放键**，点击才播 —— 正好满足"不点击就不播放"。

## 七、播放性能预算

| 指标 | 目标 | 手段 |
|---|---|---|
| 单卡片点击→起播 | ≤ 300ms（T1）/ ≤ 3s（T2 首次转码） | 预加载 metadata、缓存复用 |
| 同时播放数 | 1（P-5） | 播放前停止其他 |
| 缩略图加载 | 视口内 ≤ 100ms/张 | 懒加载 + 已缓存 |
| 2000 张滚动 | 目标 60fps（低于 30fps 视为不达标） | 分页 + 懒加载 + `content-visibility: auto` |
| 内存 | 网格 DOM 节点 ≤ 500（虚拟滚动） | 分页取数（`list_photos` 分页） |

## 八、异常与提示一览（详见 07 号文案清单）

| 情形 | 提示标题 | 入口 |
|---|---|---|
| WebView2 不可用 | 这台电脑缺少浏览组件 | 用浏览器打开 |
| T1 解码失败，自动转码 | 正在准备可播放版本…（进度） | 可继续浏览 |
| T2 转码失败 | 这段实况暂时播不出来 | 用系统播放器打开原文件 |
| T3 也失败 | 这段实况暂时播不出来 | 同上 |
| 正在用 GIF 兜底 | 动画版本（GIF 会循环播放） | — |
| 缓存写入失败 | 播放缓存写入失败（磁盘可能已满） | 改用动画版本 |
