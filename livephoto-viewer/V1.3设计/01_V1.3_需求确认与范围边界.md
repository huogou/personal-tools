## 一、用户诉求原文与澄清记录

本轮需求由三轮对话演化而来，原始表述逐条列明并标注澄清结论，避免设计阶段走偏。

| # | 原始表述（用户原话） | 澄清后的问题 | 本轮裁定 |
|---|---|---|---|
| N-1 | 「我现在要把实况照片发给朋友，我怎么发」 | 分享载体问题 | 转译为 R-11（导出安卓友好 MP4），**本轮纳入**（D6） |
| N-2 | 「gif 会一直重复播放，并不是实况 要打开图片才会播放」 | 播放交互契约问题 | 升格为**核心契约** R-03/R-04，并**推翻**现有网页查看器的"悬停自播"（D5） |
| N-3 | 「你能让 gif 不一直重复吗 有没有其他办法，只有用户点击图片才会播放，不点击就不播放的那种」 | 技术可行性 | 结论：GIF 格式**在聊天软件中必然自动循环**，无法满足"不点击就不播放"；唯一载体是 `<video>` 或网页播放 → 促成 D3 选型 |
| N-4 | 「目前查看实况照片的方式还是给我生成一个一个文件来查看，我想做成 exe 的客户端」 | 载体形态问题 | 升格为 R-01（客户端内浏览，不跳出软件） |
| N-5 | 「希望能够在客户端上查看我的实况照片并且，这个实况照片还能分类，根据我上传的照片所属分类，形成在线查看分类」 | 分类 + 在线 | 拆为 R-05…R-09（分类）与 D1（"在线"= 客户端内本地浏览） |

**关于 N-4 的前提更正（V1.0 审计已核实，本轮复核沿用）**：现状**不是"每张照片一个 HTML"**，而是单个 `网页查看器/index.html` 网格页；V1.1 的「只读预览」也**已在浏览器里播放真实视频**（非 GIF）。用户的真实痛点是「**要看动态必须跳出软件、去点开生成的文件**」，而非"文件太多"。因此 R-01 的准确表述是"**把浏览收进客户端**"，而非"合并多个 HTML"。

## 二、可验收需求项（R-01 … R-14）

优先级：**M** = 必须（MVP 即含）｜**S** = 应当（首版可延后，需评审裁定）｜**X** = 本轮不做

| ID | 需求 | 验收要点（可判定） | 优先级 |
|---|---|---|---|
| R-01 | 客户端内提供「相册」页签，浏览实况照片**不跳出软件** | EXE 主窗口含「备份 / 相册」两页签；在「相册」页完成浏览全流程，无需启动外部浏览器 | M |
| R-02 | 网格卡片**默认显示静止封面** | 载入后 100 张卡片均为静态图像，**无任何自动动图** | M |
| R-03 | **点击才播**，播完**自动回到静止封面**，再点重播 | 点击→播放；播放结束→封面复原；再次点击→从头播放。**全程仅用户点击触发** | M |
| R-04 | **取消悬停自动播放** | 鼠标悬停卡片**不得**触发播放（现有 `build_html` 的 `mouseenter` 行为在客户端视图与新版网页查看器中均须移除） | M |
| R-05 | 左侧分类栏：全部 / 未分类 / 目录相册 / 手动相册 | 四类视图均可见且可点击切换；每项显示计数 | M |
| R-06 | 源根**第一层子目录**自动归类，目录名 = 相册名；根目录散落文件归「未分类」 | 源目录 `A/xx.heic+xx.mp4` → 自动进入相册「A」；`根/yy.heic` → 「未分类」 | M |
| R-07 | 手动建相册 + 给照片归类；**一张照片可属多个相册** | 新建相册；多选照片归入；同一照片出现在 2 个相册中均可见 | M |
| R-08 | 分类结果落盘为**可读 JSON**（`相册索引.json`），随输出目录走 | 关闭重开后分类不丢；JSON 可直接打开阅读 | M |
| R-09 | 索引损坏/丢失**不影响原始照片**，可重建 | 手动破坏索引文件 → 照片仍可正常浏览与备份；可从目录结构重建索引 | M |
| R-10 | 媒体播放三轨兜底：原视频直解 → 转码 MP4 → GIF | 构造不可解码样本，走第 2/3 轨并在 UI 显式标注当前使用哪一轨 | M |
| R-11 | 导出 **H.264 MP4**（安卓友好），可直接发微信/QQ | 导出文件在安卓 Chrome 可播；微信聊天中显示静止首帧 + 播放键 | M |
| R-12 | 全程离线：**不监听端口、不发起网络请求** | 抓包/端口检查为空；代码审查无 `socket`/`http.server`/`requests` 调用 | M |
| R-13 | 原有备份 / 只读预览 / GIF / 网页查看器行为**不变** | V1.2 A 组红线全绿 + 新增回归组全绿 | M |
| R-14 | 分类操作**在客户端内完成**（前端 ↔ Python 双向桥接） | 分类栏操作不依赖任何外部编辑器 | M |
| R-15 | 相册网格支持缩略图懒加载 + 大目录滚动流畅 | 2000 张规模目录滚动无明显卡顿（量化阈值见 05 号 §8） | S |
| R-16 | 相册索引支持导入/导出（便于换机迁移） | 导出 JSON → 另一目录导入 → 分类一致 | S |
| R-17 | 「相册」页支持按日期分组视图（年/月） | 按月分组的列表可切换 | S |
| R-18 | 客户端内提供"在资源管理器中显示" | 右键卡片 → 打开所在文件夹 | S |

## 三、本轮范围（In Scope）

1. **客户端浏览骨架**：主窗口由「单页」改为「备份 / 相册」双页签（`ttk.Notebook` 或等效自绘页签），新增页签 Token 与切换动效规范。
2. **内嵌 WebView2 容器**：客户端内嵌浏览器内核，复用现有 HTML/CSS/JS 资产渲染相册网格与分类栏。
3. **相册分类体系**：三层模型（目录相册 / 手动相册 / 视图），新增 `相册索引.json` 读写与原子落盘。
4. **播放引擎重构**：三轨媒体源判定 + 转码缓存 + 封面抽取 + 播放契约实现。
5. **导出 MP4（安卓分享）**：新增导出入口与产物目录。
6. **文案与验收**：新增文案清单（07 号）、验收检查表（08 号）、测试交付要求（10 号）。

## 四、明确不做（Out of Scope）

| 项 | 原因 | 备注 |
|---|---|---|
| 局域网分享 / 公网访问 | D1 裁定纯离线；与项目"零服务器"原则冲突 | 若后续需要，另起 V1.4 独立评估 |
| `http.server` / 任何本地服务 | 违反红线 L11 | 客户端走 `file://` + 绝对路径引用 |
| 人工配对挑选 UI | V1.2 Q5 登记项，与本轮主题无关（D8） | 顺延 V1.4 |
| HEIC → JPG 独立导出 | V1.2 §2 禁用于 V1.2 轮次；本轮不纳入，避免范围膨胀 | 封面抽取已用"视频首帧"替代 HEIC 解码，无需此能力 |
| 修改 `scan_groups` / `find_live_photos` 配对规则 | 违反红线 L2/L8 | 分类在**配对之后**的独立层实现 |
| 修改 `.processed.json` 语义 | 违反红线 L8/L13 | 新增独立索引文件 |
| 替换 `dist\` 正式 EXE | 沿用 V1.2 停止条件 | 新 EXE 输出独立目录 |
| 移动 `dist\` 打包产物（T1/T4/T5 遗留项） | 属文件移动，未获授权 | 继续挂起 |

## 五、与 V1.2 的关系（三列对照）

| 维度 | V1.2 | V1.3 |
|---|---|---|
| 主窗口骨架 | 单页六区（S1→S6 状态机） | **双页签**：「备份」（V1.2 六区原样保留）+「相册」（本轮新增） |
| 核心能力 | 备份安全与流程可信 | 浏览体验与内容组织 |
| 动态载体 | 备份产物=GIF；只读预览=真实视频（跳出浏览器） | **客户端内统一**：真实视频优先，转码兜底 |
| 分类 | 仅配对三态（技术状态） | **相册分类**（内容状态），与配对状态分栏呈现 |
| 数据文件 | `.processed.json` | **新增** `相册索引.json`（与前者互不影响） |
| 新增依赖 | 无（仅 Pillow + imageio-ffmpeg） | `pywebview` + `pythonnet`（见 02 号 §5–§6） |
| 受保护函数 | 13 个 | **同 13 个继续零改动**；新增代码集中在新模块 |

## 六、未决问题与默认裁定（评审时可推翻）

| # | 问题 | 默认取值（开发即按此执行） | 评审可推翻 |
|---|---|---|---|
| Q-1 | 目录相册取第几层？ | **第一层子目录**；更深层级用「/」拼接显示（如「旅行/云南」），但归属仍记第一层 | 可 |
| Q-2 | 手动相册与目录相册同名怎么办？ | **两者独立共存**，显示为「A（手动）」与「A（目录）」，不合并 | 可 |
| Q-3 | 索引存放位置 | **输出目录根**（与 `.processed.json` 同级），随备份产物自包含；另提供导入/导出 | 可 |
| Q-4 | 转码缓存放哪 | 输出目录 `播放缓存/`，键 = 源视频相对路径 + mtime + size | 可 |
| Q-5 | 播放时是否允许自动播放首个卡片 | **禁止**（与 R-03/R-04 一致，全程仅点击触发） | 不可（用户已明确） |
| Q-6 | 悬停是否保留放大动效 | **保留缩放，不保留播放**（1.04 倍 scale，200ms） | 可 |
| Q-7 | 网格卡片比例 | 竖版 3:4（实况照片原生比例），`object-fit: cover` | 可 |
| Q-8 | 首屏默认相册 | **「全部」** | 可 |
