## 四、三条技术路线对比与裁定

| 维度 | **A. 内嵌 WebView2** | B. 纯 tkinter + 抽帧播放 | C. 维持现状（跳出浏览器） |
|---|---|---|---|
| 能否播真实视频 | ✅ 原生 `<video>`，含声音 | ⚠️ 需抽帧缓存，无声或另做音频 | ✅（外部浏览器） |
| 能否"点开才播、播完回静止" | ✅ 天然支持（`ended` 事件） | ⚠️ 需自写帧调度与状态机 | ✅ |
| HTML/CSS/JS 资产复用 | ✅ 复用现有模板 | ❌ 全部重写 | ✅ |
| 新增依赖 | pywebview + pythonnet（+0.7 MB wheel） | Pillow 已有，但需新增图像栈 | 无 |
| EXE 体积影响 | 预计 +2～6 MB（见 §6） | 几乎不变 | 0 |
| 触屏体验 | ✅ 触屏天然可用 | ⚠️ 需自研手势 | ✅ |
| 无障碍/缩放 | ✅ 网页级 | ⚠️ 受限 | ✅ |
| 实现风险 | 中（打包需 hidden import，需实测） | 中高（性能/流畅度） | 无 |
| 是否解决"跳出软件" | ✅ | ✅ | ❌ **未解决本轮核心诉求** |
| **裁定** | ✅ **采纳（D3）** | ❌ | ❌ |

## 五、WebView2 嵌入实现方式对比（路线 A 内部选型）

| 方案 | 原理 | 优点 | 缺点 | 裁定 |
|---|---|---|---|---|
| **pywebview (EdgeChromium)** | 通过 pythonnet 调 `Microsoft.Web.WebView2` | 纯 Python 写、无需写 C#/JS 桥；API 简洁；Windows 后端成熟 | 需 .NET Framework（已满足 E-3）；PyInstaller 需 hidden import | ✅ **采纳** |
| cefpython3 | 内嵌完整 Chromium | 跨浏览器一致、HTML5 最完整 | 额外 ~40–60 MB；需 VC++ 运行库 | ❌ 体积不可接受 |
| tkinterweb | 旧 IE 的 MSHTML 内核 | 纯 Python、极小 | **不支持 HTML5 `<video>`** → 直接违背 R-03 | ❌ 致命不适用 |
| 直接调 Edge COM / WinRT | 手写互操作 | 依赖最少 | 代码量大、PyInstaller 打包易碎 | ❌ 性价比差 |

## 七、风险清单

| ID | 风险 | 影响 | 缓解 | 回退 |
|---|---|---|---|---|
| RK-1 | PyInstaller 单文件模式与 pythonnet 互操作冲突（常见 `clr` 加载失败） | 无法打包 | U-02 提前验证；必要时改 `--onedir` 发行 | 退回"外挂浏览器"模式（方案 C），客户端保留"打开网页查看器"入口 |
| RK-2 | 目标机无 WebView2 运行时 | 内嵌区域白屏 | 启动时探测 `WebView2` 注册表/目录，缺失则**提示安装引导**并降级为外部浏览器 | 同上 |
| RK-3 | 真实 iPhone `.mov` 为 HEVC 且 Edge 解码失败 | 卡片播不出 | 三轨兜底（R-10）：转码 MP4 → GIF；并显式提示当前轨 | GIF 兜底已存在 |
| RK-4 | 大目录（数千张）渲染卡顿 | 浏览体验差 | R-15 懒加载 + 分页；缩略图按需生成 | 分页展示 |
