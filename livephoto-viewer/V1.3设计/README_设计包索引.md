## 二、设计核心主张（一句话版）

1. **把浏览搬回软件内**：新增「相册」页签 + 内嵌 WebView2，不跳出软件、不开端口、不联网（守住项目"零第三方服务、零联网"原则）。
2. **分类是"内容相册"，不是"配对状态"**：现有 `scan_groups` 的三态（完整/待确认/不完整）是**技术状态**；本轮新增的**相册**是用户视角的内容归类，两者在 UI 上必须分开呈现、不得混用同一套标识。
3. **播放契约写死**：默认静止封面 → **点击才播** → 播完**自动回到静止** → 再点重播；**取消现有网页查看器的"悬停自动播放"**（与用户"不点击就不播放"的明确诉求冲突）。
4. **媒体三轨兜底**：原视频直解 →（不可解时）转码 H.264 MP4 缓存 →（再失败）GIF 兜底；同一套转码产物顺带解决"发给安卓朋友"。
5. **分类索引是旁路数据**：新增 `相册索引.json`，**不触碰 `.processed.json`**、不触碰原始照片；索引损坏可丢可重建，原照片零风险。

## 四、开发红线（V1.2 十条全量继承 + V1.3 新增四条）

**继承（V1.2）**

1. 备份 / 只读预览 / GIF / HTML 四大功能回归 **100% 通过**，任何一项失败 = 整体不通过；
2. `scan_groups` / `find_live_photos` / `convert_to_gif` / `extract_cover` / `build_preview_html` / `to_file_url` / `run_preview` / 临时目录清理逻辑（`cleanup_stale_preview_dirs` / `_is_our_preview_dir`）/ `load_done` / `save_done` / `_run_ffmpeg` —— **零改动（12 个）**；`process_directory` 仅允许 V1.2 已授权的最小回调调整；**`build_html` 限丙案范围**（仅删两行悬停绑定 + 点击 toggle、满足 P-10 幂等；ChatGPT 复核"有条件通过"，见 10 号 §6 最终裁定）——**范围外任何 diff 均视为违反本条**；
3. 路径拦截：源=输出、双向嵌套一律阻止，**无普通绕过按钮**，判定失败一律停止并要求重选；
4. 空间预检：超时/失败必须明确标注"未完成检查"，不得误报空间充足；
5. 关闭与取消：备份中不存在强杀路径，只有「继续等待 / 安全取消并退出」；
6. 未验证备份前，任何文案不得引导删除原文件；
7. 程序做不到的能力不得出现可点击按钮；"原样复制"不得表述为"格式转换"；不得保证安卓图库原生识别实况照片；
8. 不得为视觉效果擅自改变配对规则、备份结果语义或 `.processed.json` 逻辑；
9. 新 EXE 输出独立目录，不覆盖 `dist\`（V1.0）与 `验收构建_V1.1\` / `验收构建_V1.2\`；
10. 新增交互必须独立测试，无测试证据一律标「未验证」。

**V1.3 新增**

11. **纯离线**：客户端浏览与分类功能**不得监听任何端口、不得发起任何网络请求**；不得引入需要账号/云服务的组件。若实现中出现 `http.server` / `socket` / `requests` 等调用，视为违反红线。**执行项（V1.1 修订，R-10）：`webview.start(http_server=False)` 为强制写法**（pywebview 该参数默认值随版本/后端变化，一旦为 True 即开本地端口）；页面一律经 `file://` 加载；代码审查清单（08 号 E-02）须包含 http_server 检查与隐式本地服务/外部依赖排查；
12. **零原始文件破坏**：客户端浏览与分类功能对原始照片**只读**；所有写入只允许落在输出目录内（转码缓存 / 索引 / 缩略图），且**不得覆盖** `原始文件/` 中的原片。
13. **不触碰增量语义**：新增 `相册索引.json` **不得**复用、合并或改写 `.processed.json`；两者互不影响，任一损坏互不牵连。
14. **不得静默降级**：媒体播放失败（转码失败、编码不支持、缓存不可写）必须**显式提示并可回退**，禁止无声换源或直接显示空白卡片。
