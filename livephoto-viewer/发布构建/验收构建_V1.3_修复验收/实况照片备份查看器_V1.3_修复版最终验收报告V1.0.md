## 三、T-01 失败与复测中止的根因分析

### 3.1 已排除（有证据）

| 假设 | 证据 | 结论 |
|---|---|---|
| 控制器不可见导致媒体挂起 | `document.visibilityState = visible` | 排除 |
| 前端状态未推送 / 网格未渲染 | `诊断\probe_frontend_state_results.json`：`A4 / offset 200 / total 627 / __lpCards 200 / .card 200` | 排除 |
| 长路径 / 中文 / 空格 | `诊断\probe_path_factor_results.json`：同页同卡片 4 种路径（path 60/66/185/121，URL 284/348/409/**861**）**全部 `playing / T1 / readyState=4`** | 排除 |
| 视频损坏 / 系统解码能力 | 同上 + 独立 Edge 对照（`probe_edge_headless_results.json`） | 排除 |

### 3.2 已确认的工具侧原因

| 编号 | 原因 | 证据 |
|---|---|---|
| A | **主线程阻塞式轮询**：`step_*` 在 Tk 主线程用 `time.sleep` 循环 + `evaluate_sync`（内部 `done.wait(20)`）等待，通信慢时主线程停止处理消息 → Windows 判定「未响应」 | Run 4 截图（「实况照片备份查看器 V1.3（未响应）」+「Python 未响应」）；`捕获瞬间={}`、`state=None` |
| B | **按索引取卡片**：损坏样本 `BROKEN.mp4` 因 mtime 最新曾排 `items[0]`，若定位失败回退 0 就会点到损坏视频 | 扫描实测 `items[0] = C_异常/broken`（修复前）；已在工具侧改为 `Z_异常` + mtime 调旧 + 禁止回退 0 |
| C | **无异常落盘保护**：进程终止即丢失结果 | 已加增量落盘（Run 4 生效，保留 T-00） |

### 3.3 工具修复记录（已改，但按负责人要求未再运行）

| 修改 | 内容 |
|---|---|
| 增量落盘 | `record()`/`unverified()` 每次调用 `_flush()` 写 `partial=true` 的 JSON |
