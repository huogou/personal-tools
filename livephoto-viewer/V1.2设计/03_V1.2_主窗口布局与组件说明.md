## 0. 设计目标（一句话）

**打开程序 5 秒内，用户能回答四个问题：这工具是干嘛的 → 我的照片在哪 → 现在扫描了吗 → 下一步点哪。**

对应现状三大断点（01 报告 §2）：开始前无引导 → 用「工作台 + 状态徽章」解决；过程中无感知 → 用「状态徽章 + 真实进度」解决；完成后无入口 → 用「结果卡片 + 快捷入口」解决。

## 1. 总体信息架构

```
┌─────────────────────────────────────────────────────────────┐
│ ① 标题区（固定高 ~72px）                                      │
│    产品名 + 版本 + 一句话说明 + 右上角「使用帮助」链接          │
├─────────────────────────────────────────────────────────────┤
│ ② 工作目录区（固定高 ~108px）                                  │
│    照片文件夹 [输入框] [浏览]   · 当前状态徽章（未开始/扫描中…） │
│    备份输出到 [输入框] [浏览]   · 增量提示行                    │
├─────────────────────────────────────────────────────────────┤
│ ③ 扫描结果区（可拉伸，最小 ~200px）                            │
│    统计卡行：6 张状态卡（总数/完整/可预览/待确认/不完整/失败）   │
│    说明行：当前最重要的一句「下一步建议」                       │
│    明细区：分类折叠列表（默认收起，见 §3）                      │
├─────────────────────────────────────────────────────────────┤
│ ④ 任务操作区（固定高 ~120px）                                  │
│    [只读预览] [开始备份] 两个主按钮 + 备份选项（折叠式）         │
│    备份完成后：追加结果卡片（打开目录/打开查看器）               │
├─────────────────────────────────────────────────────────────┤
│ ⑤ 帮助与指南区（固定高 ~64px，一行入口）                        │
│    4 张指引卡：导入电脑 / 确认配对 / 安全备份 / 传到安卓         │
├─────────────────────────────────────────────────────────────┤
│ ⑥ 日志区（唯一弹性区，fill=both+expand）                       │
│    浅色日志卡 + 状态色文字 + 内部滚动                          │
└─────────────────────────────────────────────────────────────┘
```

**缩放规则**：窗口拉伸时，②③⑤ 保持各自高度，只有 ③ 内明细列表与 ⑥ 日志区参与伸缩；宽度上所有卡片行居中且最大 820px，超出留白。

**可滚动策略（V1.2 实现反馈回写，对应实现报告 D-14）**：真实 tkinter 字体渲染下，上部内容区（①~⑤）实测总高 ≈684px，超出 860×680 窗口的 564px 内容预算——实现采用**上部内容区可滚动 Canvas + 日志区固定底部**：内容永不裁切、日志恒可见，仅当内容超出可视高度时出现细滚动条（属保证 07 号 G-2「最小尺寸无裁切」的权衡，验收按此口径）。

## 2. 各区域组件明细

### ① 标题区（~72px）

| 元素 | 规格 |
|---|---|
| 产品名 | 「实况照片备份查看器」`font.h1`，`text-primary` |
| 版本徽标 | 「V1.2」9pt，`neutral` 徽章样式，紧贴产品名右侧 8px |
| 一句话说明 | 「备份 iPhone 实况照片，让动态永远不丢」`font.caption` `text-secondary` |
| 右上角 | 「? 使用帮助」文字链接 → 打开帮助向导（见 04/05 号文档的程序内呈现方式） |

### ② 工作目录区（~108px，白卡）

| 元素 | 规格 |
|---|---|
| 行 1 | Label「照片文件夹」(body) + Entry（等宽拉伸，`highlightthickness=1` 边框 `#D0D7DE`）+ 次按钮「浏览」 |
| 行 1 右侧 | 状态徽章：○ 未开始 / ● 扫描中 / ✓ 已扫描（三态，§6 编码） |
| 行 2 | Label「备份输出到」+ Entry + 次按钮「浏览」 |
| 行 3 | 增量提示 caption：「重复备份会自动跳过已处理的照片」`text-tertiary` |
| 校验反馈 | 目录无效时 Entry 边框变 `danger` 红，右侧 caption「这个文件夹不存在，请重新选择」 |

**行为设计（回应 P0-1/P0-2）**：选完源目录即触发轻量校验（目录是否存在、是否与输出目录相同/包含、剩余空间粗估），结果以行内 caption 呈现，**不打断输入**；真正拦截发生在点「开始备份」时（见 06 号文案 #8/#9）。

### ③ 扫描结果区（核心新增，回应 P1-1/P1-2）

#### 3.1 统计卡行（6 张，各 128×88px）

| 卡 | 数字来源（程序可检测） | 说明文案（固定） |
|---|---|---|
| 总数 N | 分组总数 | 共发现 N 组照片 |
| 完整配对 | complete 数 | 图和视频都在，可以直接备份 |
| 可预览 | 含视频分组数 | 点「只读预览」就能在浏览器里看动态 |
| 待确认 | uncertain 数 | 同名文件多于一组，需要你人工看一眼 |
| 不完整 | incomplete 数 | 只有图或只有视频，先别急着删原文件 |
| 失败 | 封面提取失败数 | 个别文件读不出来，详情看日志 |

- 未扫描时：整行显示一张 640×88 的空态卡「还没有扫描 —— 选择照片文件夹后，点上面的『只读预览』」。
- 数字为 0 的卡**照常显示 0**，不隐藏（保持 6 卡位置稳定，避免跳动）。

#### 3.2 下一步建议行（关键引导，回应"每种状态告诉用户下一步"）

单行，`font.body`，前缀 ⚠/✓ 符号，文案按优先级规则动态生成（状态机见 §5）：

| 条件 | 文案示例 |
|---|---|
| 未扫描 | 「第一步：选好照片文件夹，点『只读预览』看看扫描结果」 |
| 有待确认 | 「有 N 组同名照片需要你确认，建议先点开预览页逐组核对，再决定是否备份」 |
| 有不完整 | 「有 N 组文件不完整（缺图或缺视频）。程序不会判断文件损坏，建议检查导入方式后重新扫描」 |
| 全部完整 | 「全部配对完整，可以放心点『开始备份』」 |
| 备份完成 | 「备份完成！建议打开输出目录抽查几张，确认能打开后再删除电脑或手机上的原文件」 |

#### 3.3 分类明细区（可折叠）

- 三个折叠分组：「待确认 (N)」「不完整 (N)」「失败 (N)」，每组标题行 = 徽章 + 数量 + ▸/▾ 展开符。
- 展开后每行 32px：徽章 + 文件名（超长截断）+ 来源子目录（caption 灰）。
- **完整配对不在主窗口逐条列出**（可能数百条），仅显示数量，点击「在预览页查看全部 →」打开浏览器预览页。
- tkinter 实现：`tk.Frame` + 动态 `pack_forget/pack`，或 `ttk.Treeview`（推荐后者，自带滚动）。

### ④ 任务操作区（回应 P1-5 权重问题）

```
[ 只读预览（绿·主） ]   [ 开始备份（蓝·主） ]      ——顺序即推荐顺序
  看动态，不改动文件        复制原图+视频，生成 GIF/网页

▸ 备份选项（默认收起，一行小字摘要当前选择）
    ☑ 保留原始双件套（关掉后备份里将没有原始文件，无法长期归档）
    ☑ 转为 GIF 动图（每张约 2MB，任何电脑都能看动态）
    ☑ 生成网页查看器（像手机相册一样翻看）
```

- 两个主按钮下方各配 9pt 说明，明确「预览=只读」「备份=写入」的本质区别（回应 P0-4）。
- 备份选项收纳进折叠区：默认全选延续 V1.1 行为；**取消「保留原始双件套」时，勾选框旁立即出现 ⚠ 橙色提示**（不弹窗，行内提示）。
- 备份进行中：两个主按钮同时禁用，按钮文字「备份中…」，日志区顶部出现任务卡（标题行状态徽章「● 备份中」+ 右侧**次按钮「取消备份」**，见 §6.3）。
- 备份完成：任务卡变为「✓ 备份完成 / ⚠ 部分失败 / ○ 已取消」，追加动作行「↗ 打开备份目录」「↗ 打开网页查看器」两个文字链接（回应 P1-3）。

### ⑤ 帮助与指南区（一行 4 卡，每卡 ~200×64px）

| 卡 | 标题 | 一句话 | 点击后 |

## 3. 关键用户流程（文字版流程图）

### 流程 1：首次使用（新手主线）

```
打开程序
  └→ 看到标题+说明 + 「还没有扫描」空态卡 + 下一步建议「选好文件夹点预览」
选照片文件夹 →（行内校验：目录存在 ✓ / 与输出不同 ✓ / 空间够 ✓）
点「只读预览」 → 按钮变「预览中…」 → 浏览器打开预览页
  └→ 回到主窗口：统计卡就绪 + 下一步建议按结果生成
      ├→ 有待确认/不完整 → 提示先看预览页逐组核对 → 用户核对
      └→ 全部完整 → 提示「可以开始备份」
选输出目录 →（校验）
点「开始备份」 → 摘要确认弹窗（06 号 #8 前置：备份 N 组、到哪个目录、预计空间）→ 确认
  └→ 按钮禁用「备份中…」 → 日志滚动 + 任务卡状态徽章
备份完成 → 任务卡「✓ 备份完成」+ 动作行「打开备份目录」「打开网页查看器」
  └→ 下一步建议：「抽查几张能打开后，再删原文件」
```

### 流程 2：再次使用（增量）

```
打开程序 → 选上次同一目录 → 点「只读预览」或直接「开始备份」
  └→ 摘要确认弹窗显示「上次已备份 M 组，本次将跳过 M 组、新增 K 组」→ 确认
     → 完成（已跳过条目在日志中灰色「已跳过」标注）
```

### 流程 3：传输到安卓（入口在帮助区第 4 卡）

```
帮助卡「传到安卓手机」 → 向导 B 第 1 步选目标（保素材/看动态/只要静态）
  → 第 2 步给出方案与限制（明确程序当前只能：复制双件套 / 转 GIF，见 05 号）
  → 第 3 步传输路径（USB/局域网/云盘，不绑定具体 App）
  → 第 4 步验证清单（先确认手机能打开，再考虑删电脑备份）
```

## 5. 界面状态机（V1.2 主窗口 7 态，V1.1 修订扩展）

| 态 | 触发 | 界面表现 |
|---|---|---|

## 6. P0 落地细化（V1.1 修订新增，按审查裁定 §二逐条落实）

### 6.1 路径关系判定（P0-1 强化：不得只比较字符串）

主窗口选完目录后、"开始备份"点击时，均执行以下**规范化判定**，任何一步失败即判定为"无法确认"，按拦截处理：

| 步骤 | 规则 | 说明 |
|---|---|---|
| ① 规范化 | `os.path.abspath` → `os.path.normpath` → `os.path.normcase`（Windows 大小写归一）→ 去除尾部 `\` / `/` | 统一正反斜杠、盘符大小写、相对路径解析 |
| ② 别名解析 | 尽力调用 `os.path.realpath`（解析符号链接 / junction / subst 盘）；解析失败不中断，标注"别名未完全解析" | 覆盖 Windows 常见路径别名【待验证：实机对 junction/subst 的覆盖度】 |
| ③ 关系判定 | `out == src`（相同）或 `out` 是 `src` 的前缀且紧跟路径分隔符（输出在源内部）→ **拦截**；`src` 是 `out` 的内部目录同样**拦截**（防输出嵌套导致的扫描污染，对应裁定 §二.3） | 前缀比较必须以 `os.sep` 为边界，禁止裸 `startswith` |
| ④ 判定失败兜底 | 上述任一环节抛异常或结果不可靠 → **不执行备份**，弹「无法确认两个目录的关系，请重新选择」并聚焦目录选择框 | 对应裁定"无法可靠判定时停止操作"，**不提供绕过** |

**实现要求**：判定函数独立、可单测（K 组验收）；不引入新依赖，全部用标准库 `os.path` + `ctypes`（如需 GetLongPathName 处理 8.3 短文件名，作为尽力而为项，失败按④兜底）。

### 6.2 空间预检三态（P0-2 / Q8 落地）

预检在选定输出目录后异步启动，结果以下列三态之一显示在目录区行内 caption，**禁止出现"空间充足"的模糊表述**（裁定：超时必须明确标注未完成预检）：

| 态 | 显示 | 后续行为 |
|---|---|---|
| 已完成 | 「预计需要 X GB · 目标盘可用 Y GB」或「预计需要 X GB · 目标盘可用空间不足 ⚠」 | 不足时点开始备份弹 9a 警告 |
| 超时跳过（>3s） | 「空间检查未完成（目录过大已跳过），开始备份前请自行确认磁盘剩余空间」 | 点开始备份时**再次尝试快速估算**；仍超时则弹确认「未完成空间检查，仍要继续吗」【不得静默放行】 |
| 检查失败 | 「空间检查失败（可能无读取权限），请自行确认磁盘剩余空间」 | 同超时兜底：确认后放行 |

### 6.3 安全取消机制（Q7 落地）

| 项 | 设计 |
|---|---|
| 入口 | S5 任务卡右侧次按钮「取消备份」 |
| 第一击 | 弹确认（06 号文案 #16）：「已复制完成的文件会保留，当前这张处理完后停止。确定取消吗？」[继续备份]（默认）/[确定取消] |
| 确认后 | 徽章「● 备份中」→「● 取消中」，按钮禁用变「取消中…」；**取消标志置位，当前条目完整处理完（复制/GIF 转完）后循环停止**，`.processed.json` 正常保存（已成功条目照常记录） |
| 技术路径 | **并入 Q4 最小回调调整**：per-item 回调返回 `False` 表示请求停止，`process_directory` 循环检测到后 break——不新增强杀、不中断单个文件中途写入；此为 Q4 范围内的最小改动，**请 ChatGPT 二次确认该实现路径** |
| 结束态 | S6「○ 已取消」+「已完成 N 组，其余未处理，下次备份自动续传」（增量机制天然支持续传）；日志记「[已取消] 用户取消，完成 N 组」 |
| 关闭程序 | S5/S5c 点 × 弹「继续等待 / 安全取消并退出」；选后者 = 触发同一取消标志，待循环正常退出并保存记录后程序关闭；**不提供任何强杀路径** |
