## 二、设计核心主张（一句话版）

1. **解决三大断点**：开始前无引导 → 统计卡+下一步建议行；过程中无感知 → 状态徽章+逐条进度；完成后无入口 → 结果卡+打开目录/网页链接。
2. **五项 P0 硬拦截**：源=输出拦截（不可绕过）、空间预检、备份摘要二次确认、选项后果说明、"不完整≠损坏"文案。
3. **视觉延续不推翻**：保留品牌蓝/绿，扁平直角白卡片，状态三重编码（色+符号+文字），全部 tkinter 原生可实现。

## 四、开发红线（审查裁定 §二/§四 全量收录，批准后写进开发授权）

1. 备份 / 只读预览 / GIF / HTML 四大功能回归 **100% 通过**，任何一项失败 = 整体不通过；
2. `scan_groups` / `process_directory` / `find_live_photos` / `convert_to_gif` / `extract_cover` / `build_html` / `run_preview` / 临时目录清理逻辑零改动——**唯一例外**：Q4 裁定允许对 `process_directory` 做最小回调参数调整（含取消标志经回调返回值，提请二次确认）；
3. **路径拦截**：源=输出、输出在源内部、源在输出内部一律阻止，**无普通绕过按钮**；判定不得只比较字符串（规范化 + 别名解析）；**判定失败一律停止并要求重选**；
4. **空间预检**：超时/失败必须明确标注"未完成检查"，不得误报空间充足；
5. **关闭与取消**：备份中不存在强杀路径，只有「继续等待 / 安全取消并退出」；取消 = 当前条目完整处理完后停止；
6. 未验证备份前，任何文案不得引导删除原文件（"未经验证的备份不能作为删除原文件的依据"）；
7. 程序做不到的能力不得出现可点击按钮；"原样复制"不得表述为"格式转换"；不得保证安卓图库原生识别实况照片；
8. 不得为视觉效果擅自改变配对规则、备份结果语义或 `.processed.json` 逻辑；
9. 新 EXE 输出独立目录，不覆盖 `dist\`（V1.0）与 `验收构建_V1.1\`；所有验收以实际运行 EXE 为准；
10. 新增交互（路径拦截/空间预检/进度显示/关闭处理/向导）必须独立测试（07 号 K 组），无测试证据一律标「未验证」。
