### 1.3 行为逻辑【已验证：源码行 595–638】

- 「开始备份」：要求源、输出两个目录都有效，否则弹 `messagebox.showwarning`；点击后按钮文字变「处理中…」并禁用，后台线程执行复制 + GIF 转码 + HTML 生成。
- 「只读预览扫描」：只要求源目录；点击后按钮变「预览中…」并禁用；在系统临时目录生成预览页并自动打开默认浏览器。
- 两个按钮共用的进度条：备份开始置 0 → 结束置 100；预览流程**完全不动进度条**。
- 日志区：所有输出（成功/失败/统计/警告）以纯文本行追加，滚动显示；失败原因含 ffmpeg 原始报错（中文路径下存在 GBK/UTF-8 乱码，见验收报告 W2）。
- 无任何菜单栏、无帮助入口、无版本号显示、无状态栏。

## 2. 用户完成一次备份所经过的步骤（现状动线）

**【已验证：源码流程 + 使用说明】**，共 7 步、约 6 次交互、0 处引导：

1. 双击 EXE → 打开窗口（无任何"从哪开始"的提示）
2. 点「浏览」选照片文件夹
3. 点「浏览」选输出文件夹
4. （可选）自行理解并调整 3 个勾选项——界面上没有解释每个选项的后果
5. 点「开始备份」→ 按钮变灰，日志滚动
6. 盯日志区等「统计： …」出现（进度条不动，用户无法知道还剩多少）
7. 备份完成后**没有任何完成提示**（无弹窗、无状态变化），用户需自己打开资源管理器去输出目录找产物

**缺口结论【已验证】**：完成动线上存在 3 个断点——开始前（无引导）、过程中（无进度感知）、完成后（无入口、无下一步）。这正是 V1.2 操作引导要解决的主线。

## 3. HTML 预览页现状与主窗口的视觉关系

### 3.1 预览页（只读预览扫描产出）【已验证：源码行 285–384】

- 深色主题：页面 bg `#101418`、头部 `#1a2027`、卡片 `#222`、徽标三色：完整配对 `#2f6fed`（蓝）/ 待确认 `#e0a800`（黄）/ 不完整 `#888`（灰）
- 卡片：220px 高、圆角 10、网格自适应排列；点击弹全屏 overlay 用 `<video>` 播放原始文件（file:// 引用，不复制）
- 统计行：「扫描 N · 完整配对 N · 可预览 N · 待确认/异常 N · 失败 N」以纯文本一行展示

### 3.2 与主窗口的视觉关系

| 维度 | 主窗口 | 预览页 | 关系判定 |
|---|---|---|---|
| 主题 | 浅色 `#f2f4f7` | 深色 `#101418` | **不一致**（浏览器产物页可独立成章，但两者共享"状态"概念） |
| 完整配对色 | — | 蓝色徽标 | 与主窗口「开始备份」蓝色撞色，**同一程序内蓝色含义不统一** |
| 状态表达 | 仅日志文字 | 徽标（颜色+文字） | 预览页反而比主窗口做得好，可反哺主窗口 |
| 产物关系 | 不显示任何产物入口 | 独立存在于浏览器 | 主窗口 ↔ 预览页**无相互导航**【已验证】 |

**结论**：V1.2 应把"状态徽标 + 颜色 + 图标 + 说明"的成熟做法从预览页反哺到主窗口，并统一色彩语义（蓝色留给"进行中/可继续"，避免与"完整配对"混用）。

## 4. 问题清单（分级）

> 分级依据任务书定义：P0=易误操作/数据丢失/错误理解；P1=主操作不清晰、层级混乱、状态不明显；P2=字体、间距、配色、图标、一致性；P3=装饰性提升。
> **每条均标注：已验证 / 推断。**

### P0（安全与理解风险，V1.2 必须处理）

| # | 问题 | 证据 | 说明 |
|---|---|---|---|
| P0-1 | **源目录与输出目录相同（或输出在源内部）无拦截**【已验证：源码 start() 行 595–607 仅检查目录有效性，不检查两者关系】 | 备份会把自己复制进自己的子目录，`.processed.json` 键含路径、递归扫描可能造成不可预期结果 | 必须在开始前检测并阻断 |
| P0-2 | **备份前无磁盘空间检查**【已验证：process_directory 行 170–176 无空间判断】 | 复制大视频中途磁盘满 → 半成品文件 + 失败日志，用户难判断 | 开始前估算并提示 |
| P0-3 | **开始备份无二次确认**【已验证】 | 选错源目录会立即开始复制；GIF 转码不可逆占用磁盘 | 首次备份应展示摘要（备份什么、到哪、需要多少空间）再确认 |
| P0-4 | **勾选项无任何后果说明**【已验证：行 542–544 仅 3 行纯文字】 | 用户不理解"保留原始双件套"关掉后会发生什么（产物里将没有可长期归档的原始文件） | 每个选项配一句大白话说明；关闭"保留原始"时给出警告 |

## 5. 现有功能清单（V1.2 设计不可破坏的基线）

**【已验证：源码 + V1.1 验收报告】** 以下能力已验收通过，V1.2 仅重排 UI，不得删减或改变行为：

1. 源目录递归扫描 + 同名基名配对（多候选→待确认，绝不静默合并）
2. 分类三态：complete / uncertain / incomplete（+封面提取失败计数）
3. 备份：原样复制双件套 → `原始文件\`
4. GIF：ffmpeg 转码（fps=12, 540px）→ `GIF动图\`
5. HTML 网页查看器 → `网页查看器\index.html`（引用 `../GIF动图/` 相对路径）
6. 只读预览：临时目录生成预览页，file:// 播放原始视频，跨进程临时目录清理（含归属标记校验）
7. 增量备份：`.processed.json`（键=基名小写|视频目录）
8. CLI：`--cli` / `--preview` 两种命令行模式
9. 中文/空格路径兼容（file:// 百分号编码）

**V1.2 红线**：不得改动上述逻辑；不得让预览或备份在任何新 UI 流程中被误触发；不得在未验证备份结果的情况下引导用户删除任何文件。

## 7. 结论

当前 V1.1 是一个**功能正确但视觉与引导原始**的工具：逻辑已验收可靠，但主窗口是"控件平铺 + 日志驱动"的工程界面——用户不知道先做什么、过程中没有感知、完成后没有入口。三类断点（开始前/过程中/完成后）与 P0 的 5 项安全风险，构成 V1.2 的设计主线。
