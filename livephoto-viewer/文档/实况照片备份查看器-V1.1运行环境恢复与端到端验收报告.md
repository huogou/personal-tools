## 七、测试中发现的问题与限制

### 7.1 CLI 跨进程运行时预览临时目录不被清理（轻微，真实缺陷）

- **现象**：GUI（同进程）重扫会 `shutil.rmtree` 旧预览目录；但 `--preview` 每次是独立进程，进程内全局 `PREVIEW_TEMP_DIR` 失效，旧目录残留。实测 TEMP 中一度累积 7 个 `livephoto_preview_*`。
- **影响**：仅占用磁盘（每个约 2–3 MB），不影响功能与原始文件安全。
- **归属**：属 V1.1 新增代码的卫生问题，**不影响 V1.0 备份流程**。
- **建议**：后续改为按固定命名目录覆盖或启动时清理 `livephoto_preview_*` 残留（**本轮未改代码**，因本轮限定"不增加功能/不改源码"）。

### 7.2 ffmpeg 报错信息在中文路径下显示乱码（轻微）

- **现象**：`[封面失败] BROKEN_01: ... Error opening input file C:\...\lp_iso\娴嬭瘯 婧愮洰褰昞BROKEN_01.mp4`
- **成因**：ffmpeg 子进程输出为 GBK，日志按 UTF-8 解码 → 中文路径乱码。功能不受影响。

### 7.3 同名基名跨子目录会被合并为「待确认」（规则延续，非新缺陷）

- `DUP_01` 同时存在于根目录与 `中文 子目录`，被合并为一组（photos=2 videos=2 → 待确认）。
- 成因：`scan_groups` 与 V1.0 `find_live_photos` 一样**仅按基名配对、不含目录维度**。
- 符合 V1.1 §2.4「同名多候选不得静默覆盖，应保留并标记为待确认」，但需知悉该行为。

### 7.4 损坏视频在"配对"维度仍计为完整配对（设计边界）

- `BROKEN_01`（图 + 垃圾 mp4）配对层面为 `complete`，失败仅体现在**封面提取**与**浏览器播放**两个下游环节。
- 「文件损坏/不可解码」属于完整五态诊断范畴，**本轮授权明确不做**，故未纳入分类。
