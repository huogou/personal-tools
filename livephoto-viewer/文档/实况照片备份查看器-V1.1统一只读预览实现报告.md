### 1.3 源码改动点（`LivePhoto_Backup.pyw`）

1. **新增导入**（顶部）：`webbrowser`、`tempfile`、`from urllib.parse import quote`。
2. **`to_file_url(path)`**：本地绝对路径 → `file:///` URL（中文/空格经 `quote(safe="/:")` 编码）。
3. **`scan_groups(src_dir)`**（新增，非完整五态）：沿用的 `os.walk` + 同名基名分组，但**保留全部候选**并分类：
   - `complete`：恰好 1 图 + 1 视频（可靠配对）；
   - `uncertain`：同名多候选（图或视频 >1），**不静默覆盖，标记待确认**；
   - `incomplete`：仅有图或仅有视频，**不臆断另一类已丢失**。
4. **`build_preview_html(temp_dir, items, stats)`**（新增）：生成**单一** `index.html` 网格页，每张卡片含封面（视频首帧 jpg，放临时 `thumb/`）、状态徽标、文件名；点击卡片在**同一页面 overlay** 用 `<video controls>` 播放原始视频，含「返回网格」按钮与「编码无法播放」错误提示。**引用原始文件 `file://`，不复制。**
5. **`run_preview(src_dir, log)`**（新增）：调用 `scan_groups` → 统计（总数/完整/可预览/待确认/不完整/失败）→ 在**独立临时目录**（`tempfile.mkdtemp(prefix="livephoto_preview_")`）写封面缓存与预览页 → `webbrowser.open` 打开。每次重扫先 `shutil.rmtree` 旧预览临时目录。**不写 `.processed.json`、不复制原始文件、不生成 GIF。**
6. **GUI**：新增「只读预览扫描」绿色按钮（仅用「照片文件夹」源目录，不要求输出目录）；新增 `start_preview` / `_work_preview` 与 `_poll` 中 `done_preview` 分支恢复按钮。
7. **CLI**：`main()` 新增 `--preview <源文件夹>` 模式（供无 GUI 的 EXE 隔离测试）。

## 二、关键实现说明

- **只读性**：预览全程只向 `tempfile` 临时目录写入（封面 jpg + index.html），对源目录仅做 `os.walk` 读取；无任何 `shutil.copy` / 写原始目录 / 生成 GIF 的动作。
- **配对规则**：沿用同名基名；多候选进 `uncertain`（保留、标记待确认，不覆盖）；单边文件进 `incomplete`（不宣称缺失）。
- **播放策略**：优先播放原始视频（`<video>` 原生控件，支持播放/暂停/进度）；若浏览器无法解码（如 HEVC），`video.onerror` 显示明确提示，**不崩溃、不自动批量转 GIF**（按授权要求，按需转换方案留待兼容性测试后提出）。
- **统计口径**：扫描总数 = 所有分组数；完整配对 = `complete`；可预览 = 含视频的分组；待确认/异常 = `uncertain + incomplete`；失败 = 封面提取异常数。
- **与备份隔离**：预览不触碰 `.processed.json` 与输出目录，两种模式互不污染（【推断】源码隔离；备份回归见第三章）。

## 六、已知问题与未完成事项

### 6.1 已知问题 / 限制

- **HEIC 缩略图**：浏览器无法直接显示 HEIC，预览封面取自**视频首帧**（ffmpeg），不解码 HEIC；对"仅有 HEIC、无视频"的 `incomplete` 条目无封面（显示占位文字）。【推断】
- **HEVC(.mov) 解码**：真实 iPhone 实况 `.mov` 常含 HEVC，部分浏览器无法播放 → 走 `onerror` 提示，尚未做按需 GIF 兜底（按授权暂缓）。【待验证】
- **`file://` 媒体加载**：页面本身为 `file://` 时，同机 `<video src="file:///...">` 一般可加载，但跨浏览器策略差异未实测。【待验证】
- **多候选处理**：`uncertain` 仅取首视频做预览，未做用户人工抉择 UI（属五态诊断范畴，本轮不做）。
